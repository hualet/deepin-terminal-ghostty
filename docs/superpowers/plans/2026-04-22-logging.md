# Logging Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add baseline DTK-backed logging to the app entry point and core terminal lifecycle paths, plus document project logging rules in `AGENTS.md`.

**Architecture:** Introduce a small shared logging module that owns `QLoggingCategory` declarations and defaults. Initialize DTK appenders in `src/app/main.cpp`, then consume those categories from `MainWindow`, `PtySession`, and `TerminalWidget` for lifecycle/failure logs only, avoiding hot-path spam. Update build files so the logging module is linked into the app and relevant tests.

**Tech Stack:** C++20, Qt6 `QLoggingCategory`, DTK6 `DLog`, CMake, Qt Test

### Task 3: Agent Logging Rules

**Files:**
- Modify: `AGENTS.md`

- [ ] **Step 1: Add the logging guidance**

Add a short section covering:

```md
## Logging

- Use project logging categories from `src/logging/Logging.h` instead of raw `qDebug()` or `qWarning()` in normal application code.
- Keep categories under the `org.deepin_terminal_ghostty.*` namespace.
- Use `qCInfo` for lifecycle milestones, `qCWarning` for recoverable failures or fallbacks, and `qCCritical` for unrecoverable initialization failures.
- Avoid logging in paint paths, per-byte PTY data paths, and other high-frequency loops unless handling an error.
- Failure logs should include enough context to identify the failing operation.
```
