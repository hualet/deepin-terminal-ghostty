# Internationalization Design

## Goal

Add project-level translation support with English as the source language and initial translations for Simplified Chinese (`zh_CN`) and Spanish (`es`).

## Scope

This change will:

- add Qt translation source files under `translations/`
- integrate translation extraction and release into CMake
- load application translations at startup based on the system locale
- translate UI strings that already use `tr()`

This change will not:

- rewrite large amounts of UI text
- add runtime language switching UI
- translate shell output, PTY content, or Ghostty terminal data

## Approach

Use Qt's standard i18n pipeline:

- `Qt6::LinguistTools` in CMake
- `.ts` files tracked in the repository
- `.qm` files generated during build/install
- `QTranslator` loaded in `main.cpp`

This keeps translation maintenance aligned with Qt tooling and avoids a custom resource-loading path.

## Build Integration

Update `CMakeLists.txt` to:

- require `Qt6 LinguistTools`
- define the translatable source file list for the app
- generate `.qm` files from:
  - `translations/deepin-terminal-ghostty_zh_CN.ts`
  - `translations/deepin-terminal-ghostty_es.ts`
- install generated `.qm` files into a translations directory alongside the application install

The build should continue to work when translations are already checked in and updated normally with Qt tools.

## Runtime Loading

Update `src/app/main.cpp` to:

- determine the system UI locale with `QLocale`
- attempt to load a matching app translation file
- fall back cleanly to English when no matching translation exists

The initial implementation only needs to load app translations for supported locales:

- `zh_CN`
- `es`

All other locales should continue using English source strings.

## Translation Content

Populate the initial `.ts` files with translations for current UI strings, including strings in:

- `MainWindow`
- `SettingsDialog`
- `TerminalWidget`
- `AppSettings`
- settings metadata from `default-config.json` if exposed through Qt translation extraction

If some JSON-backed settings labels are not extractable through the current pipeline, leave them in English for now rather than introducing a parallel translation system in this change.

## Testing

Verify:

- project config/build still succeeds with translation support enabled
- translation files are generated/released correctly
- app starts normally when no supported locale is active
- app loads Chinese translations under `zh_CN`
- app loads Spanish translations under `es`

For automated coverage, prefer a focused test around translation file discovery or startup loading only if it can be added cheaply. Otherwise, rely on build verification and manual runtime checks for this change.

## Risks

- Qt extraction may not cover strings stored only in JSON configuration data
- runtime translation lookup depends on install/build output paths being correct
- DTK widgets may require translator installation before window construction for all visible strings to localize properly

## Implementation Notes

- Keep English as the source text already present in code
- Do not add a settings UI for language selection in this task
- Prefer small, local CMake and startup changes over refactoring unrelated UI code
