## 新版真正解除了哪些接入阻塞

### 1. Kitty 占位图与相对定位：优先接入

当前 `TerminalWidget::renderKittyGraphicsLayer()` 使用 storage placement
iterator 和 `ghostty_kitty_graphics_placement_render_info()`，只能覆盖当前
已实现的非虚拟路径。`textual-image` 使用的 U+10EEEE 占位图仍是缺口。

1.4 新增统一的 render-state 图像列表，涵盖固定放置、Unicode 占位图，
以及以固定或虚拟放置为根的相对定位：

- `GhosttyRenderStateImageIterator`；
- `GHOSTTY_RENDER_STATE_DATA_IMAGE_ITERATOR`；
- `ghostty_render_state_image_iterator_next()`；
- `ghostty_render_state_image_get_multi()`；
- `GHOSTTY_RENDER_STATE_DATA_IMAGE_PLACEMENTS_GENERATION`。

条目已给出图像 ID、像素代际、视口坐标、像素偏移、源/目标矩形和 z 层。
关键提交包括 `17bc3e94a` 和 `48dde97e0` / #14789。

接入时让 Qt 从这个列表绘制全部 Kitty 图片，按 layer 和 z 排序，处理负视口
坐标裁剪，并跳过占位字符自身的字形绘制。不要同时保留原来的 storage
iterator 绘制路径，否则普通图片会重复绘制。可继续使用 QPainter，
不需要为了此能力更换图形后端，也无需在 Qt 重写占位符解码规则。

缓存应区分布局代际与单图像像素代际：移动图片不必重新转换像素；更新某张
图片也不必清空全部 QImage。需要覆盖 `textual-image`、Unicode placeholder
icat、相对定位、滚动/reflow、裁剪、同 ID 替换和主/备用屏切换。

上游依据：`include/ghostty/vt/render.h` 的 Images 章节、
`include/ghostty/vt/kitty_graphics.h`、`example/c-vt-kitty-graphics/src/main.c`。

### 2. Kitty 动画：所需 C API 已经提供

`8904e3284` 新增：

```c
GhosttyResult ghostty_kitty_graphics_animation_tick(
    GhosttyKittyGraphics graphics, uint64_t now_ms, uint64_t *next_ms);
```

Qt 可以使用单调时钟和 single-shot QTimer：每次准备绘制前推进一次动画，
根据返回的 `next_ms` 安排下一帧；`GHOSTTY_NO_VALUE` 表示无播放中的动画。
按图像 generation 更新像素缓存。tick 会使先前借用的图像句柄/像素指针失效，
需要重新查询。还应将调度与标签/窗口可见性连接，验证暂停、恢复、循环、
帧合成、删除和替换。

原 TODO 中“等待上游提供 tick/next-deadline”的条件已经满足，剩下的是本地
集成和验证；仅更新库不会让当前 Qt 渲染器自动播放动画。

### 3. Kitty 富剪贴板：接口早已具备，Qt 读取侧尚未接入

当前捆绑头文件已经包含 `GHOSTTY_TERMINAL_OPT_CLIPBOARD_READ`、多 MIME
内容、授权回复以及 `ghostty_terminal_paste()`。
项目只注册写回调 `effectClipboardWrite()`；它可以写入 QMimeData，
但未注册读取回调，粘贴也仍取 `clipboard()->text()`。

因此可基于现有接口补充：MIME 枚举、PNG/HTML/文本读取、mode 5522 粘贴事件。
应用层负责带预览的授权 UI、会话范围的授权记忆和大小限制，库层只暴露窄的
终端请求能力。不能把当前写回调或更新二进制等同于完整支持 OSC 5522。

这项适合面向终端 AI 工具的图片粘贴需求，但依赖客户端采用该协议，
不能保证所有 CLI 都能直接接收图片。

## 核心修复应先于新增功能

1.4 发布后的安全公告不能全部套用到我们的 Qt + VT 嵌入方式。
以下与实际代码路径有关，并且修复提交不在当前 `a4aacd918` 中：

- 滚动回退裁剪/清屏相关游标页面生命周期修复：`65ff54c67`、
  `1c2ea7222` / #14857。对应
  [GHSA-w9q4-5jvv-mcv4](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-w9q4-5jvv-mcv4)。
  属于 VT 核心，升级应覆盖，尤其需验证小回退上限、带样式/链接的游标和清屏。
- Kitty repeated walias 的内存保留限制：`44c4c8f55` / #14678。
  [Kitty 安全公告](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-mhff-mv4q-fp63)
  涉及多个问题；本项目关闭文件、临时文件和共享内存媒体，减少了相关文件路径
  的暴露，但直接传输仍启用，不能据此排除解析和资源耗尽问题。
- 粘贴保护将 CR 也视为换行：`cc53940b4` / #14687，参见
  [GHSA-4hwh-wx3w-3fqg](https://github.com/ghostty-org/ghostty/security/advisories/GHSA-4hwh-wx3w-3fqg)。
  当前 Qt 粘贴在未启用 bracketed paste 时直接写 PTY，未调用安全判定。
  所以仅升级库不能补齐应用的粘贴确认；需一并检查普通粘贴、中键粘贴和拖放入口。

tmux control mode 公告明确说明 libghostty-vt 不受影响，本次运行时查询也确认
该构建未启用此功能。macOS UI 公告不直接对应本项目。上述是代码与提交范围
核对，没有执行恶意载荷或开展完整安全审计。

## 可借鉴或暂缓的项目

| 项目 | 对本项目的判断 |
| --- | --- |
| Linux EGL/DMABUF 新渲染器 | 属于 GTK/renderer 层，不随 VT 库提供。可借鉴真实缩放、缓冲及线程设计；迁移 Qt GPU 后端是独立工程 |
| 分屏跨标签/窗口拖放 | 交互设计有价值，需在 `src/app/` 实现 pane/widget 所有权与布局迁移；PTY 会话应保持运行 |
| `ghostty +ssh` | 属于 CLI/SSH 包装层。当前 PTY 使用 `TERM=xterm-256color`，远程 terminfo 缺失的紧迫性较低；以后引入专用 terminfo 时再实现安装、缓存和降级 |
| mode 2033 可见性报告 | 对隐藏标签内的高频 TUI 有价值。核心已有报告逻辑，但当前 C API 未发现显式的终端可见性 setter；需先补齐或确认 embedder 接口 |
| 完整 snapshot 与 Kitty 状态 | 新版扩展了图片、放置和动画快照。当前会话恢复主要是 VT formatter 导出/重放；值得另做保真恢复评估，无法恢复已退出的进程 |
| `vt_write_until()` | 统一暴露 APC/DCS/OSC/ground 边界，有利于后续流转发或诊断；当前没有立即替换普通 `vt_write()` 的必要 |
| macOS 27 支持 | 项目仅支持 Linux，没有直接收益 |

## 建议顺序与升级条件

1. 先以 `v1.4.0` 固定提交重建 `libghostty-vt`，整体同步二进制和完整公共头文件；
   保留现有行为，先获得裁剪、Kitty 和终端一致性修复。
2. 在 Qt 侧补齐粘贴保护，分别验证 CR/LF、bracketed paste 结束符和各粘贴入口。
3. 接入统一图像列表和动画 tick，补齐当前 Kitty TODO 的主要缺口。
4. 根据产品需要接入富剪贴板，再考虑拖放、SSH、可见性与快照。

上游 1.4 的构建要求已变为 **Zig 0.17.0**，当前本机 `zig version` 是
`0.16.0`。旧构建文档中的 Zig 版本和优化参数不能直接照抄；上游已迁移
优化枚举命名。嵌入式库版本也不等于 Ghostty 桌面应用的版本。
本次没有安装新工具链、编译 1.4 库或验证其二进制兼容性。
